# 项目保存使用版本校验与短时排他锁

状态：采用

## 背景

Electron 和 MCP 会在读取后异步编辑同一份项目。只给写入过程加锁不能阻止旧快照覆盖新内容；自动合并台词、音频版本和角色也没有可靠的通用规则。

## 决策

以读取到的原始文件摘要为预期版本，保存时持同目录短时排他锁，锁内比较版本，再写临时文件并替换。版本元信息不落入项目 JSON。MCP 按项目对象绑定原文件，前端同会话保存串行化。

冲突时拒绝覆盖，保留内存草稿并暂停编辑，允许下载副本后确认重新载入。不提供强制覆盖或自动合并。音频清理在保存成功后进行。

## 取舍

不迁移旧数据、不引入依赖，但异常退出可能留下锁，需确认无写入任务后人工处理。不能约束不遵守锁的外部编辑器；回收站操作另行处理。生成成功后发生冲突时，新音频可能成为未引用文件，优先保全旧音频。
