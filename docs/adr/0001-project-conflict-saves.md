# 项目保存使用版本校验与短时排他锁

状态：采用

## 背景

Electron 和 MCP 会在读取后异步编辑同一份项目。只给写入过程加锁不能阻止旧快照覆盖新内容；自动合并台词、音频版本和角色也没有可靠的通用规则。

## 决策

以读取到的原始文件摘要为预期版本，保存时持目录外稳定位置的短时排他锁，锁内比较版本，再写临时文件并替换。回收站移动/还原/清理按固定顺序持有源/目标锁，避免目录移动改变锁路径。版本元信息不落入项目 JSON。MCP 按项目对象绑定原文件，前端同会话保存串行化。

冲突时拒绝覆盖，保留内存草稿并暂停编辑，自动写唯一恢复草稿，允许下载副本后确认重新载入。不提供强制覆盖或自动合并。音频清理在保存成功后进行。

## 取舍

不迁移旧数据、不引入依赖。异常退出锁记录持有进程信息，只允许显式恢复确认已退出的持有者，保留恢复证据；活锁、权限不明和旧格式锁不抢占。提交前再次比较摘要能发现部分外部编辑，但不能强制约束不遵守锁的编辑器。生成成功后发生冲突时，新音频由恢复草稿保留引用，优先保全已有音频。
