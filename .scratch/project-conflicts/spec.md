# 项目写入冲突保护

Status: ready-for-agent

## Problem Statement

Electron 与 MCP 各自读取项目后直接覆盖 project.json。另一个进程已经保存时，旧快照仍能覆盖新内容；MCP 异步任务还依赖全局当前文件，可能写错项目。

## Solution

保存时在短时排他锁内校验读取版本，只有磁盘未变化才写入。冲突拒绝覆盖，应用保留未保存内容并明确提示；重新载入由使用者显式选择，不自动合并台词或覆盖外部修改。

## User Stories

1. 作为使用者，我希望外部保存不会被应用旧快照静默覆盖。
2. 作为使用者，我希望冲突后当前草稿继续可见，并能保存草稿副本后重新载入。
3. 作为 MCP 使用者，我希望异步写回始终属于原来的项目，冲突返回可读错误。
4. 作为维护者，我希望旧项目无需迁移、不引入依赖和新配置。

## Implementation Decisions

- 共享项目文件 module 管理内容摘要版本、短时锁、临时文件写入和替换；Electron 与 MCP 使用同一个实现。
- 版本只作为进程间传输元信息，不写入 project.json；旧 JSON 格式不变。
- 已存在项目必须基于读取版本保存；首次创建只允许目标不存在。
- 锁忙立即提示可重试，不阻塞主线程；不自动抢占或删除不明锁。异常退出的遗留锁明确报告，人工确认没有写入任务后处理。
- 磁盘版本不符、文件消失、写入失败均不得破坏已有 project.json。
- MCP 按项目对象记录原文件与版本，不再依赖全局当前文件决定写入目标。
- 前端串行保存，同一会话的连续编辑可沿用刚保存的后继版本；外部冲突后停止继续落盘，保留草稿，显示固定提示。
- 草稿可下载为独立 JSON 副本；重新载入须确认未保存内容已另存，生成/AI运行时不得重新载入。

## Testing Decisions

- 先用临时项目复现两个独立调用者的旧快照覆盖，再通过相同 load/save interface 验证拒绝覆盖。
- 验证正常连续保存、新建、相同时间戳但内容改变、锁忙、错误后释放、JSON 不含元信息、跨进程同时保存最多一个成功。
- MCP 使用隔离文件系统/审计 adapter 测异步两个项目交错写回，不修改真实数据或权限环境。
- 隔离 Electron 验证冲突草稿保留、停止自动保存、重新载入确认及固定反馈；原工作台回归通过。
- 构建、MCP 冒烟、打包目录隐私检查和双轴审查。

## Out of Scope

自动内容合并、跨机器同步、外部编辑器遵守锁、用户数据迁移、回收站操作协调、生成服务端取消、增量保存。

## Further Notes

默认缩放按最新要求设为 0.9。所有测试使用系统临时目录生成夹具，不修改仓库项目、音色、音频或审计数据。
