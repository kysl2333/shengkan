# 生成请求与失败反馈完善

Status: ready-for-agent

## Problem Statement

TTS 请求在两分钟时提前失败，而工作台允许等待四分钟；引擎错误在界面展示为 JSON，MCP 会丢失 Python 错误原因。设置失败结果显示绿色；窄窗 1.6 倍缩放时播放器控件越过中栏，连续模式波形接近零宽。

## Solution

生成请求与工作台四分钟预算一致；提取引擎具体错误原因；失败反馈统一使用现有朱砂色；中栏不足时播放器使用两行布局，保留全部操作与完整进度条。

## User Stories

1. 作为配音使用者，我希望两至四分钟内完成的生成不会被客户端提前中断。
2. 作为使用者，我希望界面和 MCP 提示具体失败原因。
3. 作为使用者，我希望失败提示与成功提示在现有色彩系统中保持一致。
4. 作为窄窗使用者，我希望播放、倍速、跟随和拖动进度都可操作，不被右栏遮挡。

## Implementation Decisions

- 仅 TTS HTTP 请求改为 240 秒，健康检查仍 10 秒，普通请求仍 120 秒；不增加自动重试。
- 前端与 MCP 各自在已有请求 module 解析 error、字符串 detail 与校验数组 detail；后者保留字段位置，未知格式保持原有回退。
- 设置连接失败文字和状态点、单句生成失败 toast 强调边使用 --danger；成功不变。
- 播放器按中栏宽度适配，窄时波形独占一行，控件保留，现有单音频元素与倍速行为不变。

## Testing Decisions

- 在公开 synthesize/getVoices/getHealth 和 MCP 工具调用 seam 验证预算、错误原因与兼容回退，使用模拟响应、不调用真实 TTS。
- 按缩放时钟重现两至四分钟生成，先失败后通过。
- 隔离 Electron 触发连接和生成失败，验证日间/夜间计算颜色与 token 一致。
- 1280/1600 宽、1.6 缩放验证播放器边界与波形宽度；补充 1.0 缩放验证。
- 构建、工作台回归、离线播放回归与 MCP 冒烟均通过。所有测试脚本仅留系统临时目录。

## Out of Scope

跨进程文件锁、整体三栏重设计、台词网格、全局顶栏、模型真实性能、配置路径、MCP 权限、环境变量、依赖和用户数据。

## Further Notes

四类问题均先用独立脚本或渲染测量复现。客户端超时不等于服务端取消；本轮不改变服务端任务生命周期。
